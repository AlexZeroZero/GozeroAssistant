YSR performance correction — Windows build 1.0.13
Date: 2026-10-07

Root cause
ProcessGuard already gates host submission time using the selected performance
budget (75 -> 68%; 100 -> 90%). The YSR hardware-monitor path also decreased
this duty based on whole-GPU utilization. Driver utilization includes queued GPU
work and other applications and is not a measurement of this process's duty.
This feedback repeatedly reduced duty to 42-58% in the old 75% test.

Change
YSR, like NOID, now retains its explicit time budget. Applying a different mode
still changes duty. GPU disappearance, missing temperature, sensor timeout and
configured temperature threshold still stop the owned miner. No power limits,
clock settings, SHA-256d functions, reported-hash arithmetic, wallets or fees changed.
Native core is byte-for-byte identical to 1.0.12 (Gozero YSR CUDA 0.1.0):

These short local completed-work samples are not five-minute pool-effective rates.

The test reproduced the reported approximately 500 MH/s condition and showed

The 100% setting still reserves 10% host scheduling time as requested previously.

All three test sessions stopped normally; no test miner was left running.
