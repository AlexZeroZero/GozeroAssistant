Gozero Mac 0.1.9 — exact half-input PRL core / PRL 精确半精度输入内核

The new PRL path keeps int8 global inputs, stages them as half, and uses
simdgroup_half8x8 operands with simdgroup_float8x8 accumulators. Shared-memory
operand staging drops from 32 to 16 bits. Every integer in [-127,127] is exact
in half; each rank sums at most 128*127^2 = 2,064,512, below FP32's exact integer
limit. Integer accumulation, transcript, BLAKE3, candidate checks and proofs
are unchanged. This is not approximate mining or half-precision accumulation.
Only exact base Apple M3 opts in. Other devices keep their existing profile.
GZ_PRL_FP32=1 keeps the 0.1.8 representation with separate real G3 admission.
Original GZ_PRL_BASELINE=1 still means the older upstream profile, NOT 0.1.8.

2026-10-06 comparison against delivered 0.1.8, one M3:
2048 square, K4096: median 2.179 -> 2.284 TOPS; paired mean gain +5.00%.
4096 square, K4096: median 1.708 -> 1.925 TOPS; paired mean gain +14.59%.
The 4096 medians correspond to 0.854 -> 0.962 TMAC/s (+12.67% median ratio).
Distinct statistics must not be conflated. Eight ABBA blocks per shape,
separate persistent processes/bundles, 60-second alternating warmup, two
inflight slots. All 16 paired blocks were positive. Raw absolute rates decline
with time; this is not a claim of indefinitely sustained absolute throughput.
The short K3-only screen was approximately +7%; larger full-pipeline gains
may depend on operating state. No power/clock/temperature causation proven.

94 G3 cases passed for both the new half path and FP32 fallback, zero mismatch.
8192x8192x4096 production proof passed official Rust verification. Local mock
pool verified two proofs; corrupted proofs and mismatched existing jobs were
rejected. The original v4 admission restrictions and fastMath=false remain.

QTC: tested alternate Goldilocks reduction, wider Comba carries, their
combination, square-via-multiply, and a simpler carry condition. Gains were
-34.775%, -2.579%, -34.640%, +0.100%, -0.039%. No useful new improvement;
0.1.8 QTC is retained. Input/header midstate precomputation already exists.
PRL profiling points to matrix K3 as the dominant GPU stage; CPU allocation
is comparatively small. Raising CPU utilization alone is not the objective.

Reproduction: BUILD.txt, patch_half.py, bench_prl_builds.py.
Evidence: evidence/m3-half-tuning.json and prl-half-production-abba.json.
All rates above are local. Final 0.1.9 GUI QA: QTC received one real Kryptex
accepted share, zero rejected in 30 seconds. PRL submitted none in its short
run, so PRL external pool acceptance remains unverified.
No promise for other M-series models, long-term pool rate or power efficiency.

证明验证。QTC 新尝试未获得有效提升，继续使用 0.1.8 内核。仅验证这台

Gozero Mac 0.1.8 — Apple Silicon core tuning / 苹果芯片内核优化

QTC uses the exact Goldilocks Poseidon2 algorithm. External/internal rounds
are separated and S-box lanes use fixed indices. Candidates still pass the
CPU verifier. Dispatch grows from 262144 up to 1048576 nonces when response
time is below 40 ms and shrinks above 90 ms. These are adaptation thresholds,
not a hard deadline guarantee. Each dispatched range retains its original
count; new pool generations discard old candidates. TLS and submit unchanged.
A maximum-nonce exhaustion bug in the upstream host loop is also fixed.

PRL preserves exact FP32 arithmetic, transcript, BLAKE3 and proof validation.
Only the exact base Apple M3 selects BK32/PF0 with zero threadgroup padding
and fixed transcript register updates. Other devices retain upstream geometry.
The modified source and effective parameters change the cache/admission key;
all 94 G3 cases must pass again. Upstream adaptive job sizes remain unchanged.
GZ_PRL_BASELINE=1 retains the original profile for manual comparisons.
Cert-v4 is still not admitted. No safety/admission gate has been bypassed.

M3 measurements (2026-10-06; raw paired results in evidence/m3-tuning.json):
QTC identical 1M dispatch, kernel-only change: 20.327 -> 21.055 MH/s medians;
mean paired gain 3.38%. Worker + adaptive dispatch initial mean gain 6.11%.
Warm mixed-background run: 15.432 -> 16.300 MH/s; paired gain 7.57%.
After user stopped interactive use: 15.107 -> 16.660 MH/s; paired gain 12.66%.
These are distinct runs; the final median ratio is approximately +10.3%.

PRL initial full-pipeline 2048 square: 2.122 -> 2.212 TOPS; paired gain 4.09%.
Initial 4096-square run with concurrent desktop activity: paired gain -1.87%.
After a 90-second warmup and user idle, 4096 square: 1.609 -> 1.735 TOPS
(0.805 -> 0.867 TMAC/s); six ABBA blocks, paired gain 8.10%.
The smaller job-size experiment was inconclusive and is not enabled.
The pure K3 shader benchmark improved approximately 5%; complete pipeline
measurements include CPU preparation, GPU noise, allocation and synchronization.

All first-pass, negative and background-load samples are retained. User idle
means interactive use stopped; background applications were not terminated.
No clock/temperature hardware counters were captured; slowdown cannot be
attributed exclusively to thermal throttling. Adaptive batch tests retained
40/90 ms thresholds, the old 262144 starting size and the 1048576 upper cap.

Correctness: 25 GPU/CPU QTC comparisons, 65920 arithmetic operand pairs,
15 minimum-hash + 15 exhausted small ranges, plus 10 enlarged exhausted
ranges and 2 CPU minimum cases including U512::MAX. PRL tuned and fallback
profiles each passed all 94 G3 cases; production-sized proof passed the official
Rust verifier. A LOCAL mock pool verified two proofs and rejected corruption.
GUI/fee unit tests: 19; QTC adapter/range/batch lifecycle unit tests: 7.

All figures are local throughput, not pool-observed earnings. PRL TMAC/s is
operations/2/1e12 and cannot be compared to QTC/NOID MH/s. QTC and PRL real
external pool acceptance remains unverified. Only this Apple M3 was tested;
other M-series models are targets, not verified performance claims. Warm runs
and background applications can change rates substantially. No multi-day or
energy-efficiency claim. Original 0.5% service fee, settings, continuous mining,
bilingual GUI, menu bar and explicit Stop/Quit behavior are retained.
